# 🚀 Stone Game V

### 📝 Problem Description

There are several stones arranged in a row, and each stone has an associated value which is an integer given in the array `stoneValue`.

In each round of the game, Alice divides the row into two non-empty rows (i.e., `left row` and `right row`), then Bob calculates the value of each row which is the sum of the values of all the stones in that row:
- Bob throws away the row which has the **maximum** value, and Alice's score increases by the value of the **remaining row**.
- If the values of the two rows are **equal**, Bob lets Alice decide which row will be thrown away.
- The next round starts with the remaining row.

The game ends when there is only **one stone remaining**. Alice's score is initially zero.

Return the maximum score that Alice can obtain.

---

### 💡 Intuition & Strategy

1. **Interval Dynamic Programming (DP)**:
   * This problem is an optimal partitioning game over contiguous subarrays.
   * Define `dp[i][j]` as the maximum score Alice can achieve from the sub-row `stoneValue[i...j]`.

2. **Base Cases**:
   * When `i == j` (a single stone is left), no valid split can be made, so the score gained is `0`:
     $$dp[i][i] = 0$$

3. **Prefix Sum Optimization**:
   * Computing the sum of subarrays `stoneValue[i...k]` and `stoneValue[k+1...j]` must be fast.
   * Precompute a `prefixSum` array where:
     $$\text{rangeSum}(l, r) = \text{prefixSum}[r + 1] - \text{prefixSum}[l]$$

4. **Split Decision & Bob's Rule**:
   * Iterate over all possible partition indices $k$ from $i$ to $j - 1$:
     * $\text{leftSum} = \text{rangeSum}(i, k)$
     * $\text{rightSum} = \text{rangeSum}(k + 1, j)$
   * **Case 1 ($\text{leftSum} < \text{rightSum}$)**:
     * Bob throws away the right row. Alice keeps the left row:
       $$\text{score} = \text{leftSum} + dp[i][k]$$
   * **Case 2 ($\text{leftSum} > \text{rightSum}$)**:
     * Bob throws away the left row. Alice keeps the right row:
       $$\text{score} = \text{rightSum} + dp[k+1][j]$$
   * **Case 3 ($\text{leftSum} == \text{rightSum}$)**:
     * Alice gets to choose the more profitable branch:
       $$\text{score} = \text{leftSum} + \max(dp[i][k], dp[k+1][j])$$
   * The final answer for `dp[i][j]` is the maximum score achieved across all candidate splits $k$.

5. **Complexity**:
   * **Time Complexity**: **$O(N^3)$** — There are $O(N^2)$ states $(i, j)$, and each state iterates through at most $N$ partition points $k$. With $N \le 500$, total operations are $\approx 1.25 \times 10^8$, which comfortably passes within time limits.
   * **Space Complexity**: **$O(N^2)$** — Requires an $N \times N$ 2D table for memoization/DP state storage, along with an $O(N)$ prefix sum array.

### 💻 Java Solution

```java
/**
 * Language: Java 17
 * Time Complexity: O(N^3)
 * Space Complexity: O(N^2)
 */
public class Solution {

    private int[][] memo;
    private int[] prefixSum;

    public int stoneGameV(int[] stoneValue) {
        int n = stoneValue.length;
        memo = new int[n][n];
        prefixSum = new int[n + 1];

        // Step 1: Precompute prefix sums for O(1) range queries
        for (int i = 0; i < n; i++) {
            prefixSum[i + 1] = prefixSum[i] + stoneValue[i];
        }

        // Step 2: Solve for the full range [0, n - 1]
        return solve(0, n - 1);
    }

    private int solve(int i, int j) {
        // Base case: Single stone yields no additional points
        if (i == j) {
            return 0;
        }

        // Return cached result if already computed
        if (memo[i][j] != 0) {
            return memo[i][j];
        }

        int maxScore = 0;

        // Try all valid split points k between i and j - 1
        for (int k = i; k < j; k++) {
            int leftSum = getSum(i, k);
            int rightSum = getSum(k + 1, j);

            if (leftSum < rightSum) {
                // Bob discards right row; Alice keeps left row
                maxScore = Math.max(maxScore, leftSum + solve(i, k));
            } else if (leftSum > rightSum) {
                // Bob discards left row; Alice keeps right row
                maxScore = Math.max(maxScore, rightSum + solve(k + 1, j));
            } else {
                // Equal sums: Alice selects the path yielding the higher score
                int keepLeft = leftSum + solve(i, k);
                int keepRight = rightSum + solve(k + 1, j);
                maxScore = Math.max(maxScore, Math.max(keepLeft, keepRight));
            }
        }

        return memo[i][j] = maxScore;
    }

    private int getSum(int left, int right) {
        return prefixSum[right + 1] - prefixSum[left];
    }
}
```
### ⏱️ Complexity Analysis

| Metric | Complexity | Description |
| :--- | :--- | :--- |
| **Time Complexity** | **$O(N^3)$** | There are $O(N^2)$ distinct intervals $(i, j)$. For each interval, we check at most $N$ split points $k$. Range sums are calculated in $O(1)$ time using prefix sums. |
| **Space Complexity** | **$O(N^2)$** | The 2D memoization table `memo` takes $O(N^2)$ space. Prefix sum array and recursion call stack take $O(N)$ auxiliary space. |
