# 🎯 LeetCode: Smallest Stable Index

### 📝 Problem Description

You are given an integer array `nums` of length $n$ and an integer $k$.

For each index $i$, define its **instability score** as:
$$\text{instability score} = \max(\text{nums}[0..i]) - \min(\text{nums}[i..n - 1])$$

In other words:
- $\max(\text{nums}[0..i])$ is the largest value among the elements from index $0$ to index $i$.
- $\min(\text{nums}[i..n - 1])$ is the smallest value among the elements from index $i$ to index $n - 1$.

An index $i$ is called **stable** if its instability score is less than or equal to $k$.

Return the **smallest stable index**. If no such index exists, return `-1`.

---

### 💡 Intuition & Strategy

1. **Prefix and Suffix Boundaries**:
   For any index $i$:
   - The term $\max(\text{nums}[0..i])$ is a **prefix maximum** over the left subarray.
   - The term $\min(\text{nums}[i..n - 1])$ is a **suffix minimum** over the right subarray.

2. **Avoiding $O(n^2)$ Redundant Work**:
   - Recomputing range minimums and maximums separately for each index $i$ requires nested loops, scaling quadratically to $O(n^2)$ time and causing a Time Limit Exceeded (TLE) verdict.
   - We can precompute all suffix minimums in a single reverse pass in $O(n)$ time.
   - While iterating forward, we maintain a running prefix maximum on the fly, resolving each index's score in $O(1)$ operations.

3. **Algorithm**:
   - Create an array `suffixMin` of size $n$, where:
     $$\text{suffixMin}[n - 1] = \text{nums}[n - 1]$$
     $$\text{suffixMin}[i] = \min(\text{nums}[i], \text{suffixMin}[i + 1]) \quad \text{for } i = n - 2 \text{ down to } 0$$
   - Iterate index $i$ from $0$ to $n - 1$, keeping a running variable `prefixMax = max(prefixMax, nums[i])`.
   - Calculate $\text{score} = \text{prefixMax} - \text{suffixMin}[i]$.
   - Because the question asks for the **smallest stable index**, return the first $i$ encountered where $\text{score} \le k$.
   - If the loop finishes without meeting the condition, return `-1`.

4. **Complexity**:
   - **Time Complexity**: $O(n)$ — One reverse pass to compute `suffixMin`, followed by one forward pass to find the first stable index.
   - **Space Complexity**: $O(n)$ — Auxiliary array of size $n$ storing the precomputed suffix minimums.

---

### 💻 Java Solution

```java
/**
 * Problem: Smallest Stable Index
 * Language: Java 17
 * Time Complexity: O(n)
 * Space Complexity: O(n)
 */
class Solution {

    public int firstStableIndex(int[] nums, int k) {
        int n = nums.length;
        int[] suffixMin = new int[n];

        // Step 1: Precompute suffix minimum values from right to left
        suffixMin[n - 1] = nums[n - 1];
        for (int i = n - 2; i >= 0; i--) {
            suffixMin[i] = Math.min(nums[i], suffixMin[i + 1]);
        }

        // Step 2: Iterate left to right, maintaining the running prefix maximum
        int prefixMax = Integer.MIN_VALUE;
        for (int i = 0; i < n; i++) {
            prefixMax = Math.max(prefixMax, nums[i]);

            // Step 3: Return immediately upon encountering the first stable index
            if (prefixMax - suffixMin[i] <= k) {
                return i;
            }
        }

        return -1;
    }
}
```

### 📊 Complexity Analysis

| Complexity | Measure | Explanation |
| :--- | :--- | :--- |
| **Time Complexity** | $\mathcal{O}(n)$ | Requires one backward pass of length $n$ to populate `suffixMin`, followed by at most one forward pass of length $n$ to find the first index satisfying the condition. Each index operation is $\mathcal{O}(1)$. |
| **Auxiliary Space** | $\mathcal{O}(n)$ | Uses a single auxiliary array `suffixMin` of size $n$ to store precomputed minimums. The running prefix maximum uses $\mathcal{O}(1)$ additional memory. |
