# 🎯 LeetCode 835: Image Overlap

### 📝 Problem Description

You are given two images, `img1` and `img2`, represented as binary, square matrices of size `n x n`[cite: 1]. A binary matrix has only `0`s and `1`s as values[cite: 1].

We translate one image however we choose by sliding all the `1` bits left, right, up, and/or down any number of units[cite: 1]. We then place it on top of the other image[cite: 1]. We can then calculate the **overlap** by counting the number of positions that have a `1` in both images[cite: 1].

Note also that a translation does **not** include any kind of rotation[cite: 1]. Any `1` bits that are translated outside of the matrix borders are erased[cite: 1].

Return the **largest possible overlap**[cite: 1].

**Example 1:**
```
img1 = [[1, 1, 0],
        [0, 1, 0],
        [0, 1, 0]]

img2 = [[0, 0, 0],
        [0, 1, 1],
        [0, 0, 1]]
```
- **Input:** `img1 = [[1,1,0],[0,1,0],[0,1,0]]`, `img2 = [[0,0,0],[0,1,1],[0,0,1]]`[cite: 1]
- **Output:** `3`[cite: 1]
- **Explanation:**
  - We translate `img1` to the right by `1` unit and down by `1` unit[cite: 1].
  - The shifted coordinates of `1`s in `img1` coincide with `1`s in `img2` at `(1, 1)`, `(1, 2)`, and `(2, 2)`[cite: 1].
  - The maximum overlap achieved is `3`[cite: 1].

**Example 2:**
- **Input:** `img1 = [[1]]`, `img2 = [[1]]`[cite: 1]
- **Output:** `1`[cite: 1]

**Example 3:**
- **Input:** `img1 = [[0]]`, `img2 = [[0]]`[cite: 1]
- **Output:** `0`[cite: 1]

**Constraints:**
- $n == \text{img1.length} == \text{img1}[i].\text{length}$[cite: 1]
- $n == \text{img2.length} == \text{img2}[i].\text{length}$[cite: 1]
- $1 \le n \le 30$[cite: 1]
- $\text{img1}[i][j] \in \{0, 1\}$[cite: 1]
- $\text{img2}[i][j] \in \{0, 1\}$[cite: 1]

---

### 💡 Intuition & Strategy

1. **Relative Shift Vector Representation**:
   - Instead of trying every possible 2D shift $(dr, dc) \in [-(n-1), n-1] \times [-(n-1), n-1]$ and doing full $O(n^2)$ matrix scans (which takes $O(n^4)$ iterations with heavy constant factor), focus only on the cells with value `1`[cite: 1].
   - Any translation moving a cell $(r_1, c_1)$ from `img1` onto cell $(r_2, c_2)$ of `img2` requires a unique displacement vector[cite: 1]:
     $$\Delta r = r_2 - r_1, \quad \Delta c = c_2 - c_1$$

2. **Frequency Counting via Grouping**:
   - If multiple coordinate pairs $(p_1 \in \text{img1}, p_2 \in \text{img2})$ yield the **exact same displacement vector** $(\Delta r, \Delta c)$, then applying this shift aligns all of those corresponding points simultaneously[cite: 1].
   - Therefore, the problem reduces to[cite: 1]:
     $$\text{Largest Overlap} = \max_{(\Delta r, \Delta c)} \Big( \text{count of pairs with shift } (\Delta r, \Delta c) \Big)$$

3. **Optimized Direct Mapping vs Hash Map**:
   - Since $n \le 30$, the differences satisfy[cite: 1]:
     $$-(n - 1) \le \Delta r, \Delta c \le (n - 1) \implies -29 \le \Delta r, \Delta c \le 29$$
   - By adding an offset of $n$ (or $30$), we can map $[-n+1, n-1]$ directly into indices $[1, 2n-1]$ inside a fast primitive 2D integer array `int[2 * n + 1][2 * n + 1]`[cite: 1].
   - This avoids all boxing/unboxing overhead and hash collisions inherent to `HashMap<Integer, Integer>`[cite: 1].

### 💻 Java Solution

```java
import java.util.ArrayList;
import java.util.List;

/**
 * Problem: LeetCode 835 - Image Overlap
 * Language: Java 17 / 21
 * Time Complexity: O(n^2 + K1 * K2)
 * Space Complexity: O(K1 + K2 + n^2)
 */
class Solution {
    public int largestOverlap(int[][] img1, int[][] img2) {
        int n = img1.length;
        List<int[]> ones1 = new ArrayList<>();
        List<int[]> ones2 = new ArrayList<>();

        // Step 1: Collect coordinates of all 1s from both images
        for (int r = 0; r < n; r++) {
            for (int c = 0; c < n; c++) {
                if (img1[r][c] == 1) {
                    ones1.add(new int[]{r, c});
                }
                if (img2[r][c] == 1) {
                    ones2.add(new int[]{r, c});
                }
            }
        }

        // If either image contains no 1s, maximum overlap is trivially 0
        if (ones1.isEmpty() || ones2.isEmpty()) {
            return 0;
        }

        // Step 2: Track frequency of each relative translation vector (dr, dc)
        // dr and dc range between -(n - 1) and (n - 1).
        // Adding offset n shifts the range [-n + 1, n - 1] to [1, 2n - 1].
        int[][] shiftFreq = new int[2 * n + 1][2 * n + 1];
        int maxOverlap = 0;

        // Step 3: Pairwise displacement computation
        for (int[] p1 : ones1) {
            for (int[] p2 : ones2) {
                int dr = p2[0] - p1[0] + n;
                int dc = p2[1] - p1[1] + n;
                shiftFreq[dr][dc]++;
                if (shiftFreq[dr][dc] > maxOverlap) {
                    maxOverlap = shiftFreq[dr][dc];
                }
            }
        }

        return maxOverlap;
    }
}
```

### ⏱️ Complexity Analysis

- **Time Complexity:** $\mathcal{O}(n^2 + K_1 \cdot K_2)$[cite: 1]
  - Matrix scanning to filter out `1`s takes $\mathcal{O}(n^2)$ time[cite: 1].
  - Computing pairs and populating the shift array takes $\mathcal{O}(K_1 \cdot K_2)$ operations, where $K_1$ and $K_2$ are the number of `1` bits in `img1` and `img2`, respectively[cite: 1].
  - In the worst case where matrices are dense ($K_1, K_2 \le n^2$), the complexity is at most $\mathcal{O}(n^4)$[cite: 1]. Given $n \le 30$, $n^4 \approx 8.1 \times 10^5$, which executes in just a few milliseconds[cite: 1].
  
- **Space Complexity:** $\mathcal{O}(K_1 + K_2 + n^2)$[cite: 1]
  - Storing coordinates of `1` bits takes $\mathcal{O}(K_1 + K_2) \le \mathcal{O}(n^2)$ space[cite: 1].
  - The lookup grid `shiftFreq` requires $(2n + 1)^2 \approx 61 \times 61 = 3721$ primitive integers, which takes negligible memory ($\approx 15\text{ KB}$)[cite: 1].
