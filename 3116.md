# 🪙 3116. Kth Smallest Amount With Single Denomination Combination

### 📝 Problem Description

You are given an integer array `coins` representing coins of different denominations and an integer `k`.

You have an infinite number of coins of each denomination. However, you are **not allowed to combine** coins of different denominations.

Return the **$k^{\text{th}}$ smallest amount** that can be made using these coins.

---

### 💡 Intuition & Strategy

1. **Monotonicity & Binary Search on Answer**:
   * Let $f(M)$ be the number of distinct positive amounts $\le M$ that can be generated using single denominations.
   * As candidate value $M$ increases, $f(M)$ monotonically increases.
   * This allows finding the smallest value $M$ such that $f(M) \ge k$ via **Binary Search**.

2. **Search Space Bounds**:
   * **Lower Bound (`low`)**: $1$
   * **Upper Bound (`high`)**: $\min(\text{coins}) \times k$. With $\min(\text{coins}) \le 25$ and $k \le 2 \times 10^9$, the maximum upper bound is $5 \times 10^{10}$, requiring a standard 64-bit integer (`long`).

3. **Counting via Principle of Inclusion-Exclusion (PIE)**:
   * A value $x \le M$ is valid if it is a multiple of at least one coin in `coins`.
   * By the Principle of Inclusion-Exclusion over all non-empty subsets $S \subseteq \text{coins}$:
     $$f(M) = \sum_{S \subseteq \text{coins}, S \neq \emptyset} (-1)^{|S|-1} \left\lfloor \frac{M}{\text{LCM}(S)} \right\rfloor$$
   * Where $\text{LCM}(S)$ is the Least Common Multiple of all denominations in subset $S$.
   * If $\text{LCM}(S) > M$, that subset and any of its supersets contribute $0$ to the floor division and can be pruned immediately.

4. **Redundancy Pruning**:
   * If any coin $c_j$ is an exact multiple of another coin $c_i$ (i.e., $c_j \pmod{c_i} == 0$), any multiple of $c_j$ is already generated by $c_i$.
   * Filtering out redundant coins before running the subset generation reduces $N \le 15$, substantially cutting down the $2^N$ subset space.

5. **Complexity**:
   * **Time Complexity**: $O(2^M \cdot \log(\min(\text{coins}) \cdot k))$ where $M \le N \le 15$ is the number of filtered coins. With $2^{15} \approx 3.2 \times 10^4$ and $\approx 36$ binary search steps, total operations are $\approx 1.1 \times 10^6$, executing well within time limits.
   * **Space Complexity**: $O(N)$ for storing filtered denominations.

---

### 💻 Java Solution

```java
import java.util.Arrays;

/**
 * Language: Java 17
 * Time Complexity: O(2^M * log(min(coins) * k)) where M <= 15
 * Space Complexity: O(N)
 */
public class Solution {

    public long findKthSmallest(int[] coins, int k) {
        Arrays.sort(coins);
        int n = coins.length;

        // Step 1: Filter out redundant coins (multiples of smaller existing coins)
        boolean[] redundant = new boolean[n];
        for (int i = 0; i < n; i++) {
            if (redundant[i]) continue;
            for (int j = i + 1; j < n; j++) {
                if (coins[j] % coins[i] == 0) {
                    redundant[j] = true;
                }
            }
        }

        int validCount = 0;
        for (boolean isRedundant : redundant) {
            if (!isRedundant) validCount++;
        }

        long[] filteredCoins = new long[validCount];
        int idx = 0;
        for (int i = 0; i < n; i++) {
            if (!redundant[i]) {
                filteredCoins[idx++] = coins[i];
            }
        }

        // Step 2: Binary Search over the answer range [1, min(coins) * k]
        long low = 1;
        long high = filteredCoins[0] * (long) k;
        long result = high;

        while (low <= high) {
            long mid = low + (high - low) / 2;

            if (countMultiples(mid, filteredCoins) >= k) {
                result = mid;
                high = mid - 1;
            } else {
                low = mid + 1;
            }
        }

        return result;
    }

    /**
     * Computes the number of distinct multiples <= target using Inclusion-Exclusion.
     */
    private long countMultiples(long target, long[] coins) {
        int n = coins.length;
        long total = 0;
        int totalSubsets = 1 << n;

        for (int mask = 1; mask < totalSubsets; mask++) {
            long currentLcm = 1;
            int bitCount = 0;
            boolean overflow = false;

            for (int i = 0; i < n; i++) {
                if ((mask & (1 << i)) != 0) {
                    bitCount++;
                    currentLcm = lcm(currentLcm, coins[i]);
                    if (currentLcm > target) {
                        overflow = true;
                        break;
                    }
                }
            }

            if (!overflow) {
                if (bitCount % 2 == 1) {
                    total += target / currentLcm;
                } else {
                    total -= target / currentLcm;
                }
            }
        }

        return total;
    }

    private long gcd(long a, long b) {
        while (b != 0) {
            long temp = b;
            b = a % b;
            a = temp;
        }
        return a;
    }

    private long lcm(long a, long b) {
        return (a / gcd(a, b)) * b;
    }
}
```
### ⏱️ Complexity Analysis

| Metric | Complexity | Explanation |
| :--- | :--- | :--- |
| **Time Complexity** | $O(2^M \cdot M \cdot \log(\min(\text{coins}) \cdot k))$ | Binary search takes $\approx 36$ steps. In each step, we evaluate all $2^M - 1$ non-empty subsets via PIE, where $M \le 15$ is the number of non-redundant coins ($2^{15} \approx 3.2 \times 10^4$). Total operations are $\approx 1.1 \times 10^6$, running well within limits. |
| **Space Complexity** | $O(M)$ | Auxiliary space used to store the filtered array of unique/non-redundant denominations ($M \le N \le 15$). Uses $O(1)$ extra space during the search phase. |
